# Canonical Lead Model Specification

## 1. Concept & Rationale

The **Canonical Lead Model** is the central data contract of the AI Lead Automation system. 

When leads originate from diverse channels—such as web contact forms, Facebook Lead Ads, LINE Official Account messages, or emails—each platform delivers payloads in completely incompatible structures:
- A Facebook Lead Ad sends an array of `field_data` key-value pairs with numeric IDs.
- A LINE chat webhook sends an event object containing a `userId` and a text `message`.
- A website form sends whatever arbitrary parameter names the web developer assigned (`work_email`, `contact_number`, `inquiry_text`).

If downstream components (AI analysis, qualification, scoring, CRM synchronization) attempted to handle each platform format directly, the system would suffer from tight coupling, combinatorial complexity, and brittle code.

**Solution**:
Every external channel payload is immediately transformed by its corresponding **Channel Adapter** into the single, unified **Canonical Lead** object. Downstream nodes consume only this standardized format.

## 2. Canonical Model Structure

The Canonical Lead object is strictly defined in `schemas/lead.schema.json`.

```json
{
  "lead_id": "lead_20260925_001",
  "source": "website",
  "external_id": "form_sub_9847120",
  "contact": {
    "name": "Somchai Prasert",
    "email": "somchai.p@bangkokbites.co.th",
    "phone": "081-234-5678"
  },
  "company": {
    "name": "Bangkok Bites Restaurant Group",
    "website": "https://bangkokbites.co.th",
    "size": "11-50"
  },
  "message": "We operate 5 branches of Thai fusion restaurants in Bangkok. Our staff is overwhelmed answering repetitive customer questions on LINE OA regarding branch hours, reservations, and promotions. We want to implement an automated LINE AI customer service bot within the next 4 weeks. Budget is approved around 80,000 THB.",
  "received_at": "2026-09-25T10:00:00Z",
  "metadata": {
    "utm_source": "google_ads",
    "utm_medium": "cpc",
    "utm_campaign": "line_bot_bkk_2026",
    "landing_page": "https://example.com/solutions/line-crm",
    "ip_address": "171.96.120.45"
  }
}
```

## 3. Detailed Field Definitions

| Field Name | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `lead_id` | String | **Yes** | Internal unique identifier generated by the intake adapter (e.g., `lead_YYYYMMDD_UUID`). |
| `source` | String | **Yes** | Acquisition channel origin. Enum: `website`, `facebook`, `line`, `email`, `api`, `test`. |
| `external_id` | String / Null | No | Foreign record ID from the origin platform (e.g., Meta `leadgen_id`, LINE `userId`, form ID). |
| `contact` | Object | **Yes** | Contact information for the prospect. |
| `contact.name` | String | **Yes** | Full name or social display name. |
| `contact.email` | String / Null | No | Validated email address. Formatted in lowercase. |
| `contact.phone` | String / Null | No | Phone number, stripped of superfluous formatting. |
| `company` | Object | No | Organization details if available. |
| `company.name` | String / Null | No | Stated organization or business entity name. |
| `company.website` | String / Null | No | Company domain or URL. |
| `company.size` | String / Null | No | Company size range (`1-10`, `11-50`, `50+`). |
| `message` | String | **Yes** | The core unstructured natural language inquiry to be analyzed by AI. |
| `received_at` | String | **Yes** | ISO 8601 UTC timestamp of submission (`YYYY-MM-DDTHH:MM:SSZ`). |
| `metadata` | Object | No | Key-value dictionary preserving channel-specific tracking, UTM tags, and IP data. |

## 4. Normalization Across Channels

```text
Facebook Lead Ad
  { "field_data": [ {"name": "full_name", ...} ] } ──┐
                                                      │
Website Contact Form                                  ▼
  { "fields": { "work_email": "...", ... } } ─────────► [ Channel Adapter ] ──► [ Canonical Lead ]
                                                      ▲
LINE Official Account Chat                            │
  { "events": [ { "message": {"text": "..."} } ] } ───┘
```

### Channel Mapping Matrix

| Canonical Field | Website Adapter | Facebook Adapter | LINE OA Adapter |
| :--- | :--- | :--- | :--- |
| `lead_id` | Generated UUID | `fb_lead_{leadgen_id}` | `line_lead_{timestamp}` |
| `source` | `"website"` | `"facebook"` | `"line"` |
| `external_id` | `submission_id` | Meta `leadgen_id` | LINE `userId` |
| `contact.name` | `fields.full_name` | `field_data.full_name` | Fetched via LINE Profile API |
| `contact.email` | `fields.work_email` | `field_data.email` | Extracted from chat if provided |
| `contact.phone` | `fields.phone` | `field_data.phone_number` | Extracted from chat if provided |
| `company.name` | `fields.company` | `field_data.company_name` | Mentioned in chat context |
| `message` | `fields.inquiry_text` | Concat of custom questions | Synthesized conversation log |

---

## 5. Schema Validation

The canonical model is validated at runtime using JSON Schema Draft-07 (`schemas/lead.schema.json`).
- If an intake adapter produces a malformed object (e.g., missing required `contact.name` or unparseable `received_at`), the pipeline rejects the payload before calling any LLM APIs, preventing wasted API costs and pipeline errors.
